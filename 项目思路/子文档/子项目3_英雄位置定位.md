# 子项目3：英雄位置定位（Position Mapper）

> **定位**：阶段一的最后一道工序，负责将像素坐标翻译为地图语义标签。

---

## 1. 项目目标

将子项目2输出的像素坐标，映射到预先定义的网格地图上，输出结构化的位置信息（行列索引 + 地图符号）。

---

## 2. 输入 / 输出

| 类型 | 说明 |
|------|------|
| **输入** | 英雄在底图中的像素坐标 |
| **输入** | 底图的尺寸（正方形） |
| **输入** | 网格映射表 |
| **输出** | 网格行列 + 地图符号 |

---

## 3. 核心逻辑：数学映射 + 查表

该子项目不涉及图像处理，纯粹是坐标计算。

**主要步骤**：
1. 归一化：将像素坐标转换为 0~1 的相对坐标。
2. 离散化：将归一化坐标映射为网格行列。
3. 边界钳制：防止越界（极少出现）。
4. 查表：从映射表中读取对应位置的地图符号。
5. 兜底：未定义格子返回未知标记。

## 5. 使用方式

初始化映射器（加载网格表），调用映射函数将像素坐标转为网格位置和符号。支持单点映射和批量处理。

---

## 6. 验收标准

| 测试项 | 通过条件 |
|--------|----------|
| 映射准确性 | 已知位置的像素坐标能正确输出对应符号 |
| 边界处理 | 边缘坐标正确映射到边界网格 |
| 未定义格子 | 落入未标注格子时输出未知标记，不报错 |
| 批量性能 | 大量点的映射总耗时满足性能要求 |

---

## 7. 注意事项与已知限制

- 网格表的完整性：如果英雄频繁出现在未知格子，说明映射表覆盖不全，需要补充标注。
- 取整策略：当前采用四舍五入，更贴近"距离最近点位"的直觉。如需严格按边界划分，可改用向下取整。
- 底图尺寸必须一致：所有传入的尺寸必须相同，否则映射会偏移。

---

## 三个子项目的依赖关系

```
子项目1 (ROI检测) ──→ 子项目2 (头像匹配) ──→ 子项目3 (位置映射)
                                      │
                                      ▼
                                 网格映射表
```

- 子项目1 输出 ROI 结果供子项目2使用
- 子项目2 输出像素坐标供子项目3使用
- 子项目3 依赖网格映射表（与子项目1/2完全无关）
