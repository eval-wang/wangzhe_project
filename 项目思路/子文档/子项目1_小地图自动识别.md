# 子项目1：小地图自动识别（Auto ROI Detector）

> **定位**：阶段一的第一道工序，负责从原始视频帧中自动找到小地图的位置。

---

## 1. 项目目标

消除人工标定小地图 ROI 的环节。无论视频分辨率如何变化，程序都能在首帧自动框出小地图所在的矩形区域。

---

## 2. 输入 / 输出

| 类型 | 说明 |
|------|------|
| **输入** | 全屏图像（取视频首帧） |
| **输出** | 小地图在原始画面中的像素坐标和尺寸 |
| **持久化** | 存储为 JSON 文件，供子项目2读取 |

---

## 3. 核心逻辑：多特征投票机制

不依赖单一特征，而是多个特征同时检测，综合投票选出最可能的区域。

**主要检测特征**（具体实现细节待定）：
- 黑边矩形框检测
- 战绩按钮锚点检测
- 颜色分布特征检测

**决策流程**：
1. 分别执行多种检测，各自输出候选矩形。
2. 计算各候选矩形的加权综合得分。
3. 得分最高的矩形即为小地图区域。
4. 如果最高分仍低于阈值（兜底），则回退到默认区域。

## 5. 使用方式

导入主模块，读取首帧图像，调用检测函数获取小地图位置，保存结果供下游使用。

---

## 6. 验收标准

| 测试项 | 通过条件 |
|--------|----------|
| 分辨率适应性 | 在多种不同分辨率的视频上测试，框选误差在可接受范围内 |
| 误报率 | 不会把其他 UI 元素误识别为小地图 |
| 处理速度 | 首帧处理时间满足性能要求 |
| 兜底机制 | 当所有特征匹配失败时，输出合理的默认区域 |

---

## 7. 注意事项与已知限制

- 模板图依赖：部分检测需要提前准备模板，游戏 UI 更新后可能需要重新准备。
- 横屏 vs 竖屏：需根据录制方向调整筛选策略。
- 首帧要求：首帧应为游戏画面，建议取第 5~10 帧作为检测帧以提高稳定性。
