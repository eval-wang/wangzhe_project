# 贡献指南

> 欢迎参与。本项目处于早期快速迭代阶段，以下规范保证协作顺畅。

## 1. 分支工作流

```
main                    ← 稳定可用状态，随时可跑通 document2 全链路
 │
 ├── feature/xxx        ← 新功能（如 feature/auto-start-calibration）
 ├── fix/xxx            ← 缺陷修复
 └── docs/xxx           ← 纯文档变更
```

- 所有修改在分支上进行，验证通过后合并回 `main`；
- 合并前必跑冒烟测试（见 DEVELOPMENT.md 2.3 节）；
- 涉及产物 schema 变更的分支，必须同步更新 `docs/DATA_CONTRACTS.md`。

## 2. 提交信息规范

```
<类型>: <一句话描述>

类型：feat / fix / docs / refactor / perf / test / chore
例：feat: 阶段2 增加多进程并行与断点续跑
```

## 3. 代码规范

- 文件头部 docstring 说明：职责、输入输出、只读依赖；
- 阶段脚本遵循 `stageN_xxx.py` 命名，提供函数级入口 + `__main__` CLI；
- 路径常量集中在文件头部"可配置路径"区，不散落在函数体内；
- 新增产物目录必须遵守 `产物目录命名规范`（自动创建、可重建）；
- 打印日志带阶段前缀（`[阶段N] ...`），长任务每 10-20 帧报一次进度。

## 4. 修改建议机制（重要）

本仓库对子项目1/2/3 及素材目录**只读**。如果发现需要改动仓库外内容：

1. **不要直接改**；
2. 在本仓库创建 `修改建议\阶段N\项目N\` 目录（如 `修改建议\阶段2\项目2\`）；
3. 写入建议文档：问题描述、建议方案、影响范围、优先级；
4. 在对应子项目的下一轮迭代中评审采纳。

## 5. 配套工具规范

仓库根目录 `配套工具/` 下的可视化标注工具（如 `位置示意图.html`、`位置示意图-纯净版.html`）遵循以下约定：

- **落子交互**：左键放置/移除白色棋子，右键放置/移除黑色棋子，再次点击同色棋子移除；不要引入弹窗输入；
- **CSV 契约**：导出/导入格式统一为 `行,列,符号`，符号仅用 `W`（白）与 `B`（黑），行、列从 0 开始；若变更符号约定，必须同步 `docs/DATA_CONTRACTS.md` 与 README「配套工具」章节；
- **纯净版**：`*-纯净版.html` 只保留地图本体，去掉所有文字与控件，且页面与地图始终为正方形并自适应视口；
- **背景图**：固定背景统一指向 `相关素材/地图/正方形.png`，路径兜底策略（绝对路径 → 相对路径）保持一致。

## 6. Pull Request 检查单

- [ ] 冒烟测试通过（`(95, 143)`）
- [ ] 改动不涉及只读依赖路径
- [ ] 新增/变更的 schema 已同步 DATA_CONTRACTS.md
- [ ] 版本日志已记录（`../项目思路/版本管理/CHANGELOG.md`）
- [ ] 性能有变化的，更新 README/文档中的实测数据
- [ ] 涉及配套工具的，README「配套工具」章节与符号契约已同步
