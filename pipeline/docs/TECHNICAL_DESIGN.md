# 技术路径详解

> 本文档详述三个阶段的算法原理、参数选择与工程实现。
> 算法本体归属各子项目，本文档从 pipeline 视角做完整技术梳理。

## 阶段1：小地图抽帧与 ROI 裁切（stage1_extract.py）

### 1.1 任务

从任意长度的录屏中，以固定间隔抽帧，并把每帧画面左上角的小地图区域
裁切为统一尺寸的 186×186 正方形图。

### 1.2 算法：随机森林 ROI 回归

子项目1 训练了一个 `RandomForestRegressor`（300 棵树，max_depth=14，
`MultiOutputRegressor` 包装），输入整帧图像的 **233 维特征**，
输出小地图的归一化坐标 `(l/W, t/H, r/W, b/H)`：

| 特征组 | 维度 | 说明 |
|---|---|---|
| 左上区域网格特征 | 192 | 12×16 网格的局部统计 |
| 灰度直方图 | 24 | 全局亮度分布 |
| HSV 统计 | 6 | 色相/饱和度/明度均值方差 |
| 梯度 / 颜色比例 / 密度 / 全图参数 / 边缘先验 | 11 | 辅助定位特征 |

交叉验证 IoU ≈ 0.972。模型文件：`子项目1_小地图识别\roi_model.pkl`。

### 1.3 异常帧检测

以第一帧的裁切尺寸 `(ref_w, ref_h)` 为基准，后续帧尺寸偏差超过 **3%**
判定为异常（小地图被设置面板/战绩面板遮挡等），跳过并记入日志。
实测 document2 的 263 帧中 12 帧被跳过。

### 1.4 工程实现要点

- **顺序解码**：`cv2.VideoCapture` 逐帧读取（60.4fps × 14 分钟 ≈ 5 万帧），
  仅在 `(frame_index - start_frame) % frame_interval == 0` 时处理。
  这是耗时大头（~2.5 分钟），但实现简单且内存占用恒定。
- **时间戳嵌入文件名**：`frame_0000_40.0s.jpg`，使后续阶段无需查表即可获得时间。
- **JPEG 质量 95**：在体积与画质间取平衡（检测算法对压缩不敏感）。

### 1.5 参数表

| 参数 | 值 | 来源 |
|---|---|---|
| start_s | 40 | 产品决策：时间基准从 40s 开始 |
| interval_s | 3 | 产品决策：与总纲验收口径一致（15min ≈ 300 点） |
| end_s | 视频时长 | 跑到结束 |
| target_size | 186 | 子项目1 约定（186/20 = 9.3 px/格） |
| max_deviation | 0.03 | 子项目1 默认 |

## 阶段2：英雄头像检测（stage2_detect.py）

### 2.1 任务

在 186×186 小地图中定位指定英雄（当前：露娜·绿框）的头像圆心，
输出 `(px, py)`；未识别输出 `empty`。

### 2.2 算法：双掩膜环形模板 + 融合打分（子项目2 v0.4 定型方案）

**关键认知**：我方英雄头像外圈是 1-3px 的**圆形绿环**（非方框），
团战常被部分遮挡，泉水治疗光会把它染成青色。

检测流程：

```
186×186 BGR 图
    │
    ├─ 掩膜1: HSV green  H[45,95]  S≥50  V≥55   （常规绿环）
    └─ 掩膜2: HSV cyan   H[95,112] S≥40  V≥55   （泉水染色，覆盖率门槛更高）
    │
    ▼ 3×3 闭运算（连接断续细线）
颜色掩膜 ×2
    │
    ▼ 环形模板匹配：半径 10~14 五个圆环核分别卷积
覆盖率图（响应 = 环上同色像素占比）
    │
    ▼ 干扰抑制
  · 环有效占比 ≥ 0.60（防画面边缘虚高）
  · 环内部同色占比 ≤ 0.30（防草丛/河道实心块）
    │
    ▼ 贪婪 NMS（6px 半径，保留重叠英雄的近距双峰）
候选圆心列表
    │
    ▼ 融合身份确认：fused = NCC + RF分类器概率 + 0.3 × 覆盖率
  · NCC：候选 patch 与训练正样本参考模板的最相似 5 个归一化互相关均值
  · RF：RandomForest 分类器（含难负样本挖掘：主宰坑/基地UI/复活特效等）
    │
    ▼ fused ≥ 1.05 ? argmax 输出 : None
```

**为什么融合**：帧级对半实验（未见帧）——融合 77% > 单用 NCC 53% > 单用分类器 43%。
阈值 1.05 偏保守：优先保证"死亡时稳定输出 None"，牺牲部分召回。

子项目2 验证数据（train1，60 条标注）：全量 90.0%（圆心误差均值 1.72px），
诚实评估（未见帧）67%，无标注帧 0 误报。

### 2.3 工程实现要点

- **性能瓶颈**：单帧约 3.3s。成本集中在多半径卷积（5 个核 × 2 掩膜）
  与逐候选的分类器打分。单进程 0.3 帧/秒。
- **多进程**：`ProcessPoolExecutor(max_workers=6)`，`chunksize=4`。
  worker 函数 `_detect_one` 定义为模块级（Windows spawn 模式可 pickle）。
  实测 6 进程 1.9 帧/秒，加速比约 6×（接近线性，CPU 瓶颈）。
- **断点续跑**：结果以追加模式逐条写入 `hero_position.csv` 并 `flush()`；
  重跑时按文件名跳过已检测帧。EM 归档每次依据完整 CSV 重建
  （先清空再生成，保证与 CSV 严格一致）。

## 阶段3：网格定位 + 符号标注 + 时间格填表（stage3_locate_fill.py）

### 3.1 像素 → 网格

```
col = clamp(floor(px / 9.3), 0, 19)
row = clamp(floor(py / 9.3), 0, 19)
```

原点左上角（对方水晶侧），右下角 (19,19)（己方水晶侧）。
符号命名规范：己方半区小写、对方半区大写、数字越小越靠外
（详见 `相关素材\地图\命名格式plus.md`）。

### 3.2 网格 → 符号

查 `子项目3_数据定位\小地图位置.md`（唯一正本，182 个标注点，CSV 格式）。
查不到 → 该点记为 **UN**（未标注点），是地图补标的主要输入。

### 3.3 时间格填表规则

基础表格结构：列头 0:40 起每 90 秒一列（17 列），行头 6 行。
**一个单元格 = 15 秒时间窗**，6 行 × 15s = 90s = 一个列宽。

```
格子(col_idx, row_idx) 覆盖区间（左闭右开）：
  [ 40 + col_idx×90 + row_idx×15 , +15s )
  边界点（如恰好 55.0s）归入后一格
```

单元格值规则：

| 情况 | 值 |
|---|---|
| 正常识别且已标注 | 符号（如 `b0`、`R2`） |
| 检测失败（empty） | `EM` |
| 识别成功但未标注 | `UN` |
| 同格多个事件 | 按时间顺序 `_` 拼接，**不去重**（如 `b0_b0_b1`） |
| 无采样 | 留空 |
| time_s < 40 或超出 17 列 | 丢弃 |

### 3.4 UN 归档

落入表格范围内的 UN 事件，按 `(file, row, col)` 聚合计数写入 `UN.csv`，
并从阶段1 帧目录复制对应截图。归档目录每次重建（先清空再生成）。

## 版本锁定决策（重要）

`.venv` 的依赖版本必须与模型训练环境对齐：

| 包 | 锁定版本 | 原因 |
|---|---|---|
| opencv-python-headless | 4.10.0.84 | OpenCV 5.0 移除了 `cv2.HOGDescriptor`（子项目2 训练脚本依赖），4.10 为稳定 4.x |
| scikit-learn | 1.6.1 | 两个 .pkl 模型均用 1.6.1 训练；1.9 反序列化会产生大量警告且行为未验证 |
| numpy | 2.0.2 | 与 sklearn 1.6.1 兼容；2.5 对旧 pickle 数组有弃用警告 |
| joblib / openpyxl | 最新 | 无版本敏感 |

## 已知技术债

1. **阶段1 顺序解码**：5 万帧全量解码只为抽 263 帧，
   可改用关键帧 seek 或 ffmpeg 预抽帧（见 ROADMAP.md）。
2. **阶段2 单帧成本 3.3s**：多进程只是摊薄，算法本身有优化空间
   （如减少卷积半径档、候选早停）。
3. **EM 率偏高**：document2 实测 34/251（13.5%），
   与子项目2 诚实评估 67% 的未见帧命中率一致——需要多局标注扩充训练集。
