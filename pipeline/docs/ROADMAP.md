# 路线图

> 已知限制、计划中的改进与长期方向。按优先级排序。

## 短期（当前迭代）

- [ ] **降低 EM 率**：document2 实测 EM 34/251（13.5%），与阶段2 模型
  未见帧 67% 命中率直接相关。需要多局录像标注扩充训练集（子项目2）。
- [ ] **UN 点位补标**：利用 UN 归档（document2 有 75 个未标注点）
  完善 `小地图位置.md`，随后重跑历史 document 刷新结果。
- [ ] **LICENSE 选定**：发布 GitHub 前确定开源协议。

## 中期

- [ ] **开局时间自动校准**：当前固定 40s 起点。候选方案：检测游戏内计时器、
  小地图首次稳定出现、或手动标记一次后复用。
- [ ] **阶段1 解码加速**：顺序解码 5 万帧只为抽 263 帧。
  候选方案：ffmpeg 预抽帧、`cv2.CAP_PROP_POS_MSEC` 定点 seek。
- [ ] **红蓝方双地图**：对抗路/发育路位置随阵营互换，
  需要按对局方选择映射表（`项目3.md` 已记录该问题）。
- [ ] **多英雄支持**：阶段2 当前仅露娜·绿框，扩展标注集。

## 长期

- [ ] **轨迹质量评估**：基于时序连续性（相邻帧位置跳变幅度）
  自动标记可疑检测点，辅助人工复核。
- [ ] **阶段二（智能分析）**：积累多局数据后，挖掘刷野路线模式
  （见项目总纲"最终愿景"）。
- [ ] **配置外置**：路径常量迁移到 `config.yaml`，
  消除代码中的绝对路径，方便他人部署。

## 非目标（明确不做）

- 实时/直播流处理（产品决策：先抽帧再逐图处理）
- 红框（敌方）/ 蓝框（队友）识别（子项目2 路线图内容，不属于本仓库）
- 时空连续性修正单帧误检（与"每帧独立判断"的设计原则冲突，暂不做）
