## 一、项目目标

在子项目1输出的 ~188×188 小地图中，识别指定英雄（露娜）的绿框头像位置，输出圆心像素坐标。

---

## 二、检测策略（已定型 v2）

### 2.1 最终方案：双掩膜环形模板 + 融合打分

关键认知修正：绿框不是方框描边，而是**圆形绿环**（细 1-3px 圆弧，团战常被部分遮挡；泉水治疗光会把它染成青色）。

| 步骤 | 方法 | 说明 |
|------|------|------|
| 1 | 双通道 HSV 过滤 | green: H[45,95]；cyan: H[95,112]（泉水染色），+3×3 闭运算连接断续细线 |
| 2 | 环形模板匹配 | 半径 10-14 多尺度圆环核卷积，响应=环覆盖率，容忍部分遮挡 |
| 3 | 干扰抑制 | 环有效占比≥0.6（防边缘虚高）；环内部同色占比≤0.3（防草丛/河道实心块） |
| 4 | 贪婪 NMS（6px） | 保留重叠英雄的近距双峰 |
| 5 | 融合身份确认 | `fused = 模板NCC + RF分类器 + 0.3×覆盖率`，≥1.05 输出 argmax，否则 None |

### 2.2 已尝试但不可行的方案

| 方案 | 失败原因 |
|------|----------|
| 模板匹配（全图滑窗） | 受地图纹理干扰 |
| 圆检测 | 低分辨率碎片化严重 |
| HOG+SVM/RF 全图滑窗 | 速度慢，误检非绿框头像 |
| 纯颜色过滤后取质心 | 绿色区域轮廓不规则，质心偏离真实圆心 |
| 方框形状筛选（v1 思路） | 绿框实为圆环非方框，且常残弧，方框假设不成立 |
| 单用 RF 分类器确认 | 单局数据训练泛化差（未见帧仅 43%） |
| 单用模板 NCC 确认 | 遮挡场景退化（未见帧 53%） |

### 2.3 关键设计决策

| 决策 | 理由 |
|------|------|
| 颜色优先 → 环形模板 → 融合确认 | 绿环是最可靠定位特征；身份确认交给融合打分 |
| 融合打分（NCC+分类器+覆盖率） | 帧级对半实验：融合 77% > NCC 53% > 分类器 43% |
| 难负样本挖掘 | 用候选生成器收集主宰坑/基地UI/复活特效等"形似绿环"干扰训练分类器 |
| 阈值保守（fused≥1.05） | 保证"死亡输出 None"的稳定性优先于召回 |
| 方框标注 → 程序自动算圆心 | 人类难以肉眼定位精确圆心 |
| 绿框颜色区分阵营 | 绿框=我方、红框=敌方、蓝框=队友 |

## 三、运行方法

### 3.1 环境要求

```bash
pip install opencv-python numpy pillow scikit-learn
```

### 3.2 标注工具

```bash
cd release
python hero_label_tool.py
```

| 操作 | 方式 |
|------|------|
| 打开目录 | 点击"打开目录" → 选择小地图目录 |
| 画正方形框 | 鼠标拖拽（拖拽过程始终保持正方形） |
| 微调 | 方向键 1px / Shift+方向键 5px |
| 切换阵营 | 按 1(绿框) / 2(红框) / 3(蓝框) |
| 确认下一张 | Enter |
| 清除当前标注 | Backspace 或 R |
| 保存 | Ctrl+S → `hero_labels.json` |

### 3.3 标注数据格式

```json
[{
  "file": "frame_0001_10.0s.jpg",
  "boxes": [
    [48, 123, 72, 147, "green"]
  ]
}]
```

- 每个 box：`[left, top, right, bottom, label]`
- 强制正方形：`right - left == bottom - top`
- 圆心 = `((l+r)/2, (t+b)/2)`

### 3.4 训练脚本

```bash
python train_hero_model.py
```

从标注数据提取正样本（含数据增强）+ 随机负样本 + 难负样本挖掘，训练 RandomForest
分类器，并把正样本原始 patch 作为 NCC 参考模板，一并保存到 `release/hero_model.pkl`。

### 3.5 检测脚本

```bash
python hero_detect.py <图片路径>     # 单张检测，输出 (px, py) 或 None
python hero_detect.py --validate     # 在 train1 上对照标注全量验证 + 调试图
```

状态：✅ 已完成。验证结果见 `../validation_report.md`：

| 指标 | 结果 |
|------|------|
| 全量验证命中率（训练帧，偏乐观） | 54/60 (90.0%)，圆心误差均值 1.72px |
| 诚实评估命中率（帧级对半，未见帧） | 20/30 (67%) |
| 无标注帧（英雄死亡/消失） | 正确拒绝 11/11（诚实评估下 0 误报） |
| 候选生成召回率 | 27/30 (90%) |

### 4.3 不支持场景

- 非绿框英雄（红框/蓝框未标注）
- 英雄头像完全被遮挡
- 结算画面/过场动画
- 非 ~188×188 分辨率

## 五、改进空间

### 5.1 短期（方案验证）

1. **验证颜色过滤效果**：确认 HSV 阈值能稳定捕获绿框像素
2. **形状筛选调参**：边长阈值、宽高比阈值
3. **多帧测试**：在 train1 全量数据上验证

### 5.2 中期（方案确认后）

4. **多英雄标注**：标注红框（敌方）和蓝框（队友）样本
5. **轻量 CNN**：如果颜色方案不稳定，训练专用分类器
6. **NMS 后处理**：多检测结果非极大值抑制

### 5.3 长期

7. **端到端检测**：直接从 188×188 小地图输出所有英雄位置+阵营
8. **时序追踪**：利用帧间连续性修正单帧误检
