# 子项目2 英雄头像识别 - SOP 文档

> **版本**：v1.0（最终版）
> **日期**：2026-08-14
> **状态**：达到预期效果，检测管线可用
> **目标英雄**：露娜（绿框头像）

---

## 一、项目目标

在子项目1输出的 ~186×186 小地图中，识别目标英雄（露娜）的**绿色圆环头像**位置，输出圆心像素坐标。

- 输入：单张小地图图片（~186×186）
- 输出：圆心坐标 `(px, py)`；若判断目标不在场/不可见则输出 `None`

---

## 二、设计思路（最终方案 v2）

### 2.1 核心认知

绿框**不是方框描边，而是圆形绿环**（细 1-3px 圆弧），且团战中常被部分遮挡，泉水治疗光会把它染成青色。这是贯穿整个方案的关键前提。

### 2.2 检测管线

```
186×186 小地图
  │
  ├─ 1. 双通道 HSV 颜色过滤
  │      green: H[45,95]  S>50 V>55   （绿环本色）
  │      cyan : H[95,112] S>40 V>55   （泉水治疗光把绿环染青，覆盖率门槛更高）
  │      + 3×3 闭运算连接 1-3px 断续细线
  │
  ├─ 2. 环形模板匹配（半径 10-14 多尺度卷积）
  │      响应 = 环上同色像素覆盖率，可容忍部分遮挡
  │      抑制项：
  │        环有效占比 ≥0.6（防边缘虚高）
  │        环内部同色占比 ≤0.3（防草丛/河道实心块）
  │
  ├─ 3. 贪婪 NMS（半径 6px）→ 候选圆心列表
  │
  └─ 4. 身份确认融合打分
         fused = NCC(候选, 参考模板 top5 均值) + RF分类器概率 + 0.3×覆盖率
         fused ≥ 1.05 才输出 argmax 候选，否则输出 None
```

### 2.3 关键设计决策

| 决策 | 理由 |
|------|------|
| 颜色优先 → 环形模板 → 融合确认 | 绿环是最可靠定位特征；身份确认交给融合打分 |
| 融合打分（NCC + 分类器 + 覆盖率） | 实验：融合 77% > 仅 NCC 53% > 仅分类器 43% |
| 难负样本挖掘 | 用候选生成器收集"形似绿环但非目标"的干扰（主宰坑、基地UI、复活特效）训练分类器 |
| 阈值保守（fused ≥ 1.05） | 保证"死亡输出 None"的稳定性优先于召回 |
| 方框标注 → 程序自动算圆心 | 人类难以肉眼精确定位圆心 |

### 2.4 已尝试但不可行的方案

| 方案 | 失败原因 |
|------|----------|
| 模板匹配（全图滑窗） | 受地图纹理干扰 |
| 圆检测 | 低分辨率碎片化严重 |
| HOG+SVM/RF 全图滑窗 | 速度慢，误检非绿框头像 |
| 纯颜色过滤后取质心 | 绿色区域轮廓不规则，质心偏离真实圆心 |
| 方框形状筛选（v1 思路） | 绿框实为圆环非方框，且常残弧 |

## 三、训练数据

### 3.1 数据目录（当前 4 局）

| 目录 | 路径 | 标注数 |
|------|------|--------|
| train1 | `D:\wangzhe_project\selected_screenshot_collection\train1` | 60 |

| train4 | `D:\wangzhe_project\screenshot_collection\train_collection\train4` | 82 |
| train5 | `D:\wangzhe_project\screenshot_collection\train_collection\train5` | 77 |
| **合计** | | **263 条** |

> 数据目录列表在 `train_hero_model.py` 和 `hero_detect.py` 顶部的 `DATA_DIRS` 中维护，需同步修改。

### 3.2 标注格式

每个目录下 `hero_labels.json`：

```json
[{
  "file": "frame_0000_0.0s.jpg",
  "boxes": [
    [82, 130, 108, 156, "green"]
  ]
}]
```

- 每个 box：`[left, top, right, bottom, label]`，label 取 `green`/`red`/`blue`
- 强制正方形：`right - left == bottom - top`
- 圆心 = `((l+r)/2, (t+b)/2)`

### 3.3 训练样本构成

- **正样本**：绿框标注 patch + 数据增强（旋转 ±8° / 亮度 0.85~1.15 / 水平翻转 / 平移 ±2px），10 倍扩充
- **负样本**：随机采样（每正样本配 4 个）+ **难负样本挖掘**（每图最多 20 个，"像绿环但非目标"的候选）
- **特征**：HSV 颜色直方图（18×8）+ HOG 梯度特征，拼接为 468 维
- **模型**：RandomForest（200 棵树，depth 12）与 SVM（RBF）对比，5-fold F1 择优

## 四、使用方法

### 4.1 环境要求

```bash
pip install opencv-python numpy pillow scikit-learn
```

### 4.2 标注新数据（可选）

```bash
python hero_label_tool.py
```

| 操作 | 方式 |
|------|------|
| 打开目录 | 点击"打开目录" → 选择小地图目录 |
| 画正方形框 | 鼠标拖拽（始终正方形） |
| 微调 | 方向键 1px / Shift+方向键 5px |
| 切换阵营 | 1(绿) / 2(红) / 3(蓝) |
| 确认下一张 | Enter |
| 清除 | Backspace 或 R |
| 保存 | Ctrl+S → `hero_labels.json` |

### 4.3 训练模型

```bash
python train_hero_model.py
```

输出模型到 `release/hero_model.pkl`（含分类器 + NCC 参考模板）。

### 4.4 检测

```bash
python hero_detect.py <图片路径>     # 单张检测，输出 (px, py) 或 None
python hero_detect.py --validate     # 在 DATA_DIRS 所有目录上全量验证 + 调试图
python hero_detect.py --no-clf <图>  # 纯颜色+环形模板，不用分类器
```

调试图输出到 `debug_output/<目录名>/`（蓝=标注真值，黄=候选，红=最终输出）。

## 五、当前效果

### 5.1 全量验证（4 目录，模型见过这些帧，偏乐观）

| 指标 | 结果 |
|------|------|
| 图片总数 | 299（有标注 263） |
| 命中率（圆心误差 ≤5px） | 230/263 (**87.5%**) |
| 无标注帧误报 | 8 |
| 圆心误差 | 均值 2.48px，中位 1.41px |

### 5.2 泛化能力（历史关键数据）

| 训练数据 | 未见数据命中率 |
|----------|---------------|
| 仅 train1 | 20/30 (67%) |
| train1+3+4 → 测 train5 | 63/77 (**81.8%**)，误报 0 |

> 结论：多局数据扩充显著改善泛化（67% → 81.8%），且未见数据误报降至 0。

## 六、失败模式与已知局限

| 类型 | 表现 | 原因 |
|------|------|------|
| 保守拒答（漏检） | 输出 None，但候选存在 | 目标被遮挡/泉水染色，融合分低于阈值 |
| 重叠误选 | 偏差 6~72px | 两个英雄头像紧贴，相邻头像得分略高 |
| 严重误选 | 偏差 >100px | 干扰项（基地UI等）clf 分虚高压过真值 |
| 完全遮挡 | 无法检测 | 绿环覆盖率≈0，属不支持场景 |

### 当前不支持场景

- 非绿框英雄（红框/蓝框未纳入训练）
- 英雄头像完全被遮挡
- 结算画面/过场动画
- 非 ~186×186 分辨率

## 七、后续调整思路（按性价比排序）

### 7.1 短期（数据驱动）

1. **继续扩充数据**：从新对局标注（尤其团战、泉水、死亡场景），加入 `DATA_DIRS` 后重跑 `train_hero_model.py` + `hero_detect.py --validate`。
2. **难样本定向收集**：把漏检帧（如保守拒答的遮挡样本）做针对性增强，或专门标注难负样本。

### 7.2 中期（算法优化）

3. **时序一致性约束**（针对大偏差/重叠误选，最推荐）：
   - 利用帧间连续性，用前一帧位置约束当前帧候选选择；
   - 可同时修正重叠误选和离群跳变（>100px 那类）。
4. **更鲁棒的身份特征**：
   - 当前 `fused = ncc + clf + 0.3×cov` 三者等权，被遮挡时 ncc/clf 会同时失效；
   - 可引入**颜色直方图相似度**（对遮挡更鲁棒）或调整三者权重。
5. **轻量 CNN**：若颜色方案在多局泛化仍不稳定，升级为专用分类器。

### 7.3 长期

6. **端到端检测**：直接从小地图输出所有英雄位置 + 阵营。
7. **时序追踪**：多帧联合优化，系统性修正单帧误检。

---

## 八、注意事项

1. **换英雄**（非露娜）：需重新标注训练，模型是英雄专属的。
2. **换分辨率**：需重调环半径范围 `RING_RADII`（当前 10-14 对应 ~186×186）。
3. **数据目录变更**：`DATA_DIRS` 在 `train_hero_model.py` 和 `hero_detect.py` 中**各有一份**，必须同步修改。
4. **调试图体积**：全量验证会为每帧生成调试图，`debug_output/` 会快速膨胀，可用 `--no-debug` 关闭。
